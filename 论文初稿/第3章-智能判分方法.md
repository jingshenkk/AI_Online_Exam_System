# 第3章 基于LangChain的智能判分方法

本章详细阐述系统中智能判分模块的设计思路和实现方案。首先介绍评分模型的整体设计思路，然后分别说明评分细则自动生成链和学生答案评分链的结构，接着介绍宽松模式与严格模式（多模型投票）的评分流程，最后通过对比实验验证方案的有效性。

## 3.1 模型设计思路

### 3.1.1 问题分析

在主观题评分场景中，教师的批改过程通常遵循一个隐含的逻辑：先在脑中将标准答案拆解为若干关键知识点，再逐一检查学生答案是否涵盖了这些知识点，最后根据覆盖情况汇总得分。这个过程可以形式化表述为：

设一道主观题的总分为S，标准答案可以拆解为n个得分点 $P = \{p_1, p_2, ..., p_n\}$，每个得分点 $p_i$ 的分值为 $s_i$，且 $\sum_{i=1}^{n} s_i = S$。对于学生答案A，评分过程就是对每个得分点 $p_i$ 判定一个命中状态 $h_i \in \{FULL, MISS\}$，其中FULL表示该知识点被正确覆盖（得 $s_i$ 分），MISS表示未覆盖（得0分）。最终得分为：

$$Score(A) = \sum_{i=1}^{n} s_i \cdot \mathbb{1}[h_i = FULL]$$

这种逐点评分方式相比整体评分有两个优势：一是可解释性强，系统可以告诉学生具体哪些知识点答对了、哪些遗漏了；二是评分粒度可控，教师可以根据教学需要调整得分点的数量和分值分配。

### 3.1.2 方案概述

基于上述分析，本系统设计了一个两阶段的智能评分方案：

第一阶段：评分细则生成。教师在创建主观题时提供题目和标准答案，系统调用LLM将标准答案拆解为结构化的评分细则（得分点列表）。教师审核通过后，这些评分细则作为后续评分的依据。

第二阶段：学生答案评分。学生提交答案后，系统根据题目的评分模式（宽松/严格），调用LLM对每个得分点进行逐点判定，汇总得分后写入成绩记录。

两个阶段都通过LangChain的LCEL管道语法构建为标准化的处理链，实现了提示词模板、LLM调用和输出解析的解耦。

## 3.2 评分细则生成链

### 3.2.1 链结构

评分细则生成链（rubric_chain）的结构为：

$$RUBRIC\_GENERATE\_TEMPLATE \rightarrow ChatOpenAI \rightarrow JsonOutputParser$$

该链接收三个输入变量：题目文本（question）、标准答案（standard_answer）和总分（total_score），输出一个包含得分点列表的JSON对象。

表3.1展示了评分细则生成链的输入输出规范。

表3.1 评分细则生成链输入输出规范

| 字段 | 类型 | 方向 | 说明 |
|------|------|------|------|
| question | string | 输入 | 题目文本 |
| standard_answer | string | 输入 | 标准答案 |
| total_score | string | 输入 | 总分 |
| points | array | 输出 | 得分点列表 |
| points[].description | string | 输出 | 得分点描述 |
| points[].score | number | 输出 | 该得分点分值 |
| points[].acceptable_expressions | array | 输出 | 可接受的同义表达 |

### 3.2.2 提示词设计

评分细则生成的提示词采用了角色设定和格式约束的设计策略。提示词的核心要求包括：

（1）角色设定为"出题教师"，引导模型从教师视角进行答案拆解。

（2）明确要求所有得分点的分值之和等于总分，保证分值分配的完整性。

（3）要求每个得分点列出常见的同义表达，扩展评分时的匹配范围。

（4）限制输出格式为纯JSON，避免模型生成多余的解释性文本。

表3.2 评分细则生成流程伪代码

| 1 | 输入：question, standard_answer, total_score |

## 3.3 学生答案评分链与评分模式

### 3.3.1 评分链结构

学生答案评分链（score_chain）的结构为：

$$SCORE\_ANSWER\_TEMPLATE \rightarrow ChatOpenAI \rightarrow JsonOutputParser$$

该链接收三个输入变量：题目文本（question）、评分细则的JSON描述（points）和学生答案（answer），输出每个得分点的命中判定和最终总分。

表3.4展示了评分链的输出格式。

表3.4 学生答案评分链输出格式

| 字段 | 类型 | 说明 |
|------|------|------|
| point_scores | array | 逐点评分结果列表 |
| point_scores[].point_id | string | 得分点ID |
| point_scores[].hit | string | 命中判定：FULL或MISS |
| point_scores[].earned | number | 该点实际得分 |
| point_scores[].reason | string | 判定理由 |
| total | number | 总分 |

评分链的提示词设计强调了语义匹配优先的原则："同义表达、合理改写视为正确（FULL），关键概念缺失或逻辑错误（MISS），不要因格式或字面措辞扣分，关注语义是否正确"。这一设计使得LLM在评分时能够识别学生用不同措辞表达相同含义的情况，避免因为表述差异导致误判。

### 3.3.2 宽松模式

宽松模式（Lenient）是系统的默认评分模式，适用于日常练习和作业批改等对评分精度要求不高的场景。其流程如下：

（1）系统从数据库中获取该题目已审核通过的所有评分细则。

（2）将答题记录状态从PENDING更新为SCORING。

（3）调用评分链（score_chain），传入题目、评分细则和学生答案，获取逐点评分结果。

（4）遍历每个得分点的评分结果，创建ScorePointDetail记录，保存LLM-1的命中判定、得分和理由。

（5）汇总所有得分点的得分，计算最终总分。

（6）将答题记录状态更新为SCORED，写入最终总分。

表3.5以伪代码形式展示了宽松模式的评分流程。

表3.5 宽松模式评分流程伪代码

| 步骤 | 操作 |
|------|------|
| 1 | 获取题目question和已审核的评分细则points |
| 2 | 设置answer_record.status = SCORING |
| 3 | result = score_chain.invoke(question, points, answer) |
| 4 | FOR EACH point IN points: |
| 5 | &emsp;查找result中对应point_id的评分结果detail |
| 6 | &emsp;创建ScorePointDetail(llm_1_hit, llm_1_score, llm_1_reason) |
| 7 | &emsp;设置final_hit = detail.hit, final_score = detail.earned |
| 8 | &emsp;total_score += detail.earned |
| 9 | 设置answer_record.final_score = round(total_score, 1) |
| 10 | 设置answer_record.status = SCORED |

### 3.3.3 严格模式

严格模式（Strict）通过三次独立评分和逐点投票来提高评分的稳定性，适用于期末考试等对评分精度要求较高的场景。其核心思想是：同一份答案由三个独立的LLM评分过程分别判定，对每个得分点取多数票（2/3以上）作为最终结果。

严格模式的投票逻辑如下：对于每个得分点，三次评分分别给出FULL或MISS的判定。由于只有两种取值，三票中必然有一种取值出现至少两次。如果FULL出现2次或以上，则最终判定为FULL，该得分点得满分；否则判定为MISS，得0分。

表3.6以伪代码形式展示了严格模式的投票算法。

表3.6 严格模式投票算法伪代码

| 步骤 | 操作 |
|------|------|
| 1 | 输入：votes（3次评分结果列表），point（当前得分点） |
| 2 | 初始化计数器：full_count = 0, miss_count = 0 |
| 3 | FOR EACH vote IN votes: |
| 4 | &emsp;IF vote.hit == "FULL": full_count += 1 |
| 5 | &emsp;ELSE: miss_count += 1 |
| 6 | IF full_count >= 2: |
| 7 | &emsp;final_hit = "FULL", final_score = point.score |
| 8 | &emsp;vote_count = full_count |
| 9 | ELSE: |
| 10 | &emsp;final_hit = "MISS", final_score = 0 |
| 11 | &emsp;vote_count = miss_count |
| 12 | 输出：(final_hit, final_score, vote_count) |

严格模式的完整流程在宽松模式的基础上增加了两个环节：一是三次独立调用评分链（每次调用之间间隔0.3秒，避免并发请求导致的响应一致性问题）；二是对每个得分点执行投票算法。ScorePointDetail记录中同时保存了三个LLM的独立评分结果（llm_1/2/3_hit、llm_1/2/3_score、llm_1/2/3_reason）和投票后的最终结果（final_hit、final_score、vote_count），便于后续分析和调试。

### 3.3.4 评分编排

系统通过GradingOrchestrator类统一管理评分流程。当学生提交主观题答案后，系统创建一条AnswerRecord记录（状态为PENDING），然后根据该题目的评分模式（grading_mode字段）选择对应的评分服务：

（1）若grading_mode为LENIENT，调用LenientGradingService执行宽松模式评分。

（2）若grading_mode为STRICT，调用StrictGradingService执行严格模式评分。

评分过程中如果LLM调用失败，系统会将答题记录状态回退为PENDING，不会出现卡死在SCORING状态的情况。教师也可以通过手动调分接口对AI评分结果进行修正。

## 3.4 实验结果

### 3.4.1 数据集

为了验证智能评分方案的有效性，本文构建了一个包含90条样本的测试数据集。数据集由generate_dataset.py脚本借助LLM自动生成，涵盖计算机网络、操作系统、数据库原理、数据结构与算法、软件工程等5个学科方向，共30道简答题。每道题包含题目文本、标准答案和3到8个评分细则，满分均为10分。

对于每道题，脚本生成了3条不同质量梯度的学生回答，具体描述如表3.7所示。

表3.7 数据集质量梯度说明

| 质量等级 | 说明 | 样本数 |
|---------|------|--------|
| HIGH | 回答完整准确，覆盖所有得分点 | 30 |
| MEDIUM | 回答部分正确，存在遗漏或表述不够精确 | 30 |
| LOW | 回答存在明显错误或大量缺失 | 30 |

数据集共计90条样本（30题 × 3梯度），保存在dataset.json文件中。

人工评分方面，邀请了3位计算机相关专业背景的评分员对90条样本独立打分（0到10分），评分前统一了评分标准。取三人均值作为人工评分基准（human_score_avg）。

### 3.4.2 评价指标

实验采用以下四个指标评估AI评分与人工评分之间的一致性：

（1）皮尔逊相关系数（Pearson r）。衡量AI评分与人工评分的线性相关程度，取值范围为-1到1，越接近1表示越一致。计算公式为：

$$r = \frac{\sum_{i=1}^{n}(x_i - \bar{x})(y_i - \bar{y})}{\sqrt{\sum_{i=1}^{n}(x_i - \bar{x})^2} \cdot \sqrt{\sum_{i=1}^{n}(y_i - \bar{y})^2}}$$

（2）平均绝对误差（MAE）。AI评分与人工评分的平均偏差，单位为分，越小越好。

$$MAE = \frac{1}{n}\sum_{i=1}^{n}|x_i - y_i|$$

（3）均方根误差（RMSE）。对较大偏差更敏感的误差指标，越小越好。

$$RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(x_i - y_i)^2}$$

（4）评分一致率（±1分）。AI评分与人工评分差距在1分以内的样本占比，越高越好。

其中 $x_i$ 为AI评分，$y_i$ 为人工评分均值。

#### 3.4.3.3 评分细则引导的作用

对比"有评分细则"（宽松/严格模式）和"无评分细则"（无要点引导模式）的结果，差异主要体现在MEDIUM质量样本上：有引导的MAE（0.55到0.62）远优于无引导（1.34），一致率（83.33%）远高于无引导（53.33%）。这说明评分细则能够帮助LLM精确判断哪些知识点被覆盖、哪些被遗漏，验证了本系统"逐点评分"设计的合理性。

#### 3.4.3.4 宽松模式与严格模式的对比

两种模式在总体指标上非常接近（r差0.005，MAE差0.002），但严格模式的一致率（75.56%）略高于宽松模式（72.22%），在LOW样本上的改善更为明显（43.33% vs 33.33%）。这表明投票机制确实能减少极端偏差。不过严格模式的API调用量是宽松模式的3倍，在实际使用中需要权衡精度和成本。

#### 3.4.3.5 实验结论

基于上述实验结果，可以得出以下结论：

（1）LLM评分与人工评分高度一致。皮尔逊相关系数达到0.95，MAE不到1分，一致率超过72%，具备替代人工阅卷的基本能力。

（2）评分细则引导能显著提升评分精度。在"部分正确"的答案上，有评分细则引导的模式比无引导模式的MAE降低了约60%，一致率提升了30个百分点。

（3）投票机制能提高评分稳定性。严格模式的一致率比宽松模式高约3个百分点，在低分段的改善更为明显。

（4）LLM方法远优于传统关键词匹配。皮尔逊r从0.71提升到0.95，MAE从2.80降低到0.80，一致率从36%提升到72%以上。

## 3.5 本章小结

本章详细阐述了基于LangChain的智能判分方法。系统通过LCEL管道语法构建了评分细则生成链和学生答案评分链，实现了提示词模板、LLM调用和输出解析的标准化流程。在评分策略上，系统提供了宽松模式（单LLM评分）和严格模式（三LLM投票）两种选择，通过逐点评分保证了评分结果的可解释性，通过多模型投票提高了评分的稳定性。

实验结果表明，本方案的LLM评分与人工评分的皮尔逊相关系数达到0.95，平均绝对误差不到1分，评分质量接近人工水平，验证了方案的可行性和有效性。
