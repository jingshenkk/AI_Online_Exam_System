# 第2章 相关研究基础

本章介绍系统开发过程中涉及的关键技术和理论基础，包括大语言模型与提示词工程、LangChain应用开发框架、Django Web框架、Vue前端框架，以及JWT认证和RESTful API等通用Web技术。

## 2.1 基本概念

### 2.1.1 大语言模型

大语言模型（Large Language Model, LLM）是基于Transformer架构，在大规模文本语料库上通过自监督学习训练得到的神经网络模型。2017年Vaswani等人提出了Transformer架构，其核心是自注意力（Self-Attention）机制，能够对输入文本中任意两个位置之间的依赖关系进行建模。后续的GPT系列模型采用了Transformer的Decoder结构，通过"预测下一个词"的预训练任务，在数千亿参数的规模下展现了强大的语言理解和生成能力。

本系统使用的DeepSeek-V3.2是由DeepSeek公司发布的大语言模型，采用Mixture-of-Experts（MoE）架构，在中英文语义理解任务上表现良好。系统通过OpenAI兼容的API接口调用该模型，以较低的推理成本获得高质量的文本理解和结构化输出能力。

### 2.1.2 提示词工程

提示词工程（Prompt Engineering）是指通过设计和优化输入给大语言模型的提示文本（Prompt），引导模型产生符合预期的输出的技术。在本系统中，提示词工程主要应用在两个场景：

（1）评分细则生成。系统向LLM提供题目文本、标准答案和总分，通过提示词引导模型将标准答案拆解为若干个独立的得分点，每个得分点包含描述、分值和可接受的同义表达。

（2）学生答案评分。系统向LLM提供题目、评分细则和学生答案，通过提示词引导模型逐点判断学生答案是否覆盖了每个得分点，并以结构化的JSON格式返回判定结果。

提示词的质量直接影响评分结果的稳定性。本系统在设计提示词时遵循了几个原则：明确角色设定（"你是阅卷老师"）、规定输出格式（JSON模板）、给出判定规则（FULL/MISS二值判定）、限制输出范围（"只输出JSON，不要输出其他内容"）。

### 2.1.3 自动评分

自动评分（Automated Scoring）是指利用计算机技术对学生的文本答案自动给出分数的过程。按照技术路线，自动评分方法大致可以分为三类：

（1）基于关键词匹配的方法。对标准答案和学生答案进行分词，统计关键词的匹配程度来估算得分。该方法实现简单，但无法识别同义改写，对表述方式的变化敏感。

（2）基于深度学习的方法。使用LSTM、BERT等模型对答案文本进行编码，训练回归模型直接预测分数。该方法需要大量带标注的训练数据，且评分结果缺乏可解释性。

（3）基于大语言模型的方法。利用LLM的语义理解能力，通过提示词引导模型对答案进行判定。该方法无需训练数据，可以通过提示词控制评分粒度，具有较好的可解释性。

本系统采用第三种方法，并在此基础上提出了"逐点评分 + 多模型投票"的方案，在保持可解释性的同时提高评分的稳定性。

## 2.2 模块与方法

### 2.2.1 LangChain框架

LangChain是一个面向大语言模型应用开发的开源框架，由Harrison Chase于2022年发布。该框架的设计目标是将LLM的调用过程标准化、模块化，使开发者能够以组合的方式构建复杂的LLM应用。

本系统主要使用了LangChain的以下三个核心组件：

（1）PromptTemplate（提示词模板）。允许开发者定义包含占位变量的提示词模板，在运行时通过传入具体参数生成最终的提示文本。与Python原生的字符串格式化相比，PromptTemplate提供了输入变量的声明和校验机制，便于模板的复用和管理。

（2）ChatOpenAI（聊天模型封装）。对OpenAI兼容的API接口进行了统一封装，支持设置模型名称、温度参数（temperature）、最大输出长度（max_tokens）等参数。通过该组件，系统可以方便地切换不同的LLM服务商或模型版本。

（3）JsonOutputParser（JSON输出解析器）。自动从LLM的原始文本响应中提取JSON内容，处理可能存在的Markdown代码块标记（如```json），将文本解析为Python字典对象。该组件减少了手动编写解析逻辑的工作量，也降低了因LLM输出格式不稳定导致的解析失败风险。

LangChain还提供了LCEL（LangChain Expression Language）管道语法，允许使用"|"运算符将多个组件串联为一条处理链。例如，本系统的评分调用链表示为：

PromptTemplate | ChatOpenAI | JsonOutputParser

这条链的执行过程是：PromptTemplate接收输入变量，渲染为完整的提示文本；ChatOpenAI将提示文本发送给LLM，获取原始响应；JsonOutputParser从响应中解析出结构化的JSON结果。整条链通过一次invoke()调用即可完成从输入到结构化输出的全部流程。

表2.1展示了LangChain核心组件的功能说明。

表2.1 LangChain核心组件说明

| 组件 | 所属模块 | 功能 |
|------|---------|------|
| PromptTemplate | langchain_core.prompts | 提示词模板定义与变量渲染 |
| ChatOpenAI | langchain_openai | OpenAI兼容API的聊天模型封装 |
| JsonOutputParser | langchain_core.output_parsers | LLM响应的JSON结构化解析 |
| LCEL管道语法 | langchain_core | 组件串联与调用链编排 |

### 2.2.2 Django Web框架

Django是一个基于Python的高级Web框架，遵循MVT（Model-View-Template）设计模式。本系统使用Django 4.2.8作为后端框架，主要利用了以下特性：

（1）ORM（对象关系映射）。Django的ORM允许开发者通过Python类定义数据模型，框架自动生成对应的数据库表结构和SQL语句。系统中所有的数据模型（如Student、Questions、ExamResult等）都通过Django ORM定义，支持字段约束、默认值、索引等数据库特性。

（2）数据迁移（Migration）。Django提供了自动化的数据库迁移工具，在模型定义发生变化时，通过makemigrations和migrate命令自动生成和执行数据库变更脚本，避免了手动编写SQL语句的工作。

（3）中间件（Middleware）。Django的中间件机制允许在请求处理的各个阶段插入自定义逻辑。本系统通过自定义中间件实现了请求日志记录和JWT认证等功能。

本系统还使用了Django REST Framework（DRF）3.14.0作为RESTful API的开发框架。DRF在Django的基础上提供了序列化器（Serializer）、通用视图（APIView）、分页器（Pagination）等组件，简化了API接口的开发。

### 2.2.3 Vue前端框架

Vue是一个渐进式JavaScript前端框架，本系统的前端部分基于Vue 3.4构建，采用Composition API编写组件逻辑。相关的技术栈包括：

（1）TypeScript。作为JavaScript的超集，TypeScript提供了静态类型检查，有助于在开发阶段发现类型错误，提高代码的可维护性。

（2）Element Plus。基于Vue 3的桌面端UI组件库，提供了表格、表单、对话框、分页器等常用组件，系统的管理界面均基于Element Plus构建。

（3）Pinia。Vue 3推荐的状态管理库，用于在多个组件之间共享状态。系统中试卷预览、在线考试等涉及多组件协同的场景通过Pinia管理状态。

（4）Vue Router。Vue官方的路由管理器，支持嵌套路由、路由守卫等特性。系统通过路由守卫实现了基于JWT的登录状态检查和基于角色的页面访问控制。

（5）Axios。基于Promise的HTTP客户端，系统通过Axios拦截器在每个请求的Header中自动附加JWT Token，实现了统一的认证处理。

### 2.2.4 JWT认证机制

JSON Web Token（JWT）是一种基于JSON的开放标准（RFC 7519），用于在各方之间安全地传输声明信息。JWT由三个部分组成：Header（头部，声明签名算法）、Payload（载荷，包含用户信息和过期时间等声明）、Signature（签名，用于验证Token的完整性）。

本系统采用djangorestframework-simplejwt库实现JWT认证，配置了两种Token：

（1）Access Token：有效期7天，用于API请求的身份验证。前端在登录成功后将Access Token存储在本地，后续每个请求通过Authorization头部携带该Token。

（2）Refresh Token：有效期14天，用于在Access Token过期后获取新的Access Token，避免用户频繁重新登录。

系统还自定义了JWT Token的载荷，在标准字段之外增加了user_type字段，用于标识用户角色（student/teacher/admin），后端认证中间件根据该字段从对应的数据表中查询用户信息。

### 2.2.5 RESTful API设计

REST（Representational State Transfer）是一种软件架构风格，RESTful API遵循该风格，使用HTTP方法（GET、POST、PUT、DELETE）对资源进行操作。本系统的后端接口遵循以下设计规范：

（1）使用名词表示资源。例如/api/question表示试题资源，/api/examResult表示考试结果资源。

（2）使用HTTP方法表示操作。GET获取资源、POST创建资源、PUT更新资源、DELETE删除资源。

（3）统一响应格式。所有接口返回统一的JSON结构，包含code（状态码）、msg（提示信息）和data（数据）三个字段。表2.2列出了系统使用的主要状态码。

表2.2 系统响应状态码

| 状态码 | 含义 | 使用场景 |
|-------|------|---------|
| 200 | 操作成功 | GET/PUT/DELETE请求成功 |
| 201 | 创建成功 | POST请求创建资源成功 |
| 400 | 请求错误 | 参数缺失或格式不正确 |
| 401 | 未授权 | Token无效或已过期 |
| 403 | 禁止访问 | 权限不足 |
| 404 | 资源不存在 | 请求的资源未找到 |
| 500 | 服务器内部错误 | 后端异常 |

## 2.3 本章小结

本章介绍了系统开发所依赖的关键技术基础。大语言模型和提示词工程为主观题智能评分提供了核心能力；LangChain框架将LLM调用过程标准化，通过PromptTemplate、JsonOutputParser和LCEL管道语法降低了开发复杂度；Django和Vue分别负责后端业务逻辑和前端交互界面；JWT和RESTful API则保障了前后端之间的安全通信。这些技术共同构成了本系统的技术栈，为后续章节中智能判分方法的设计和系统功能的实现奠定了基础。
